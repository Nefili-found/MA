代码生成提示词
你是一名资深 Python / LangGraph 架构师。请根据以下需求，生成一个可运行的架构骨架 + 关键接口项目。不要生成完整业务逻辑；凡是需要我后续补充的地方，请用 TODO、空字符串、占位实现或注释明确标注，并同步写入 QUESTION.md。

1. 项目目标
构建一个多 Agent 代码漏洞扫描系统：

A、B、C 三个扫描 Agent，从三个视角扫描同一个 C 源码文件，生成统一 JSON 格式的漏洞判断报告。

A/B/C 使用并行 fan-out 图结构，但允许顺序调度。

D 是汇总 Agent，必须等 A/B/C 三份报告全部输入后才启动。

D 负责：

用 LLM 语义相似度去重；
调取对应报告的判断内容，裁决冲突并判断置信度；
将原始报告、生成 Agent、工具调用、D 的假设验证推断写入记忆库；
调用工具验证污点假设；
输出精简后的最终 JSON 报告。
D 必须具备调用工具的能力。

最终报告用于后续修复 Agent。

2. 技术栈与环境
Python 3.11+

LangGraph

Linux 环境

SQLite 作为记忆库

LLM 提供商可配置；代码中读取环境变量，不硬编码密钥

生成代码时，凡是需要 API Key 的地方，标注 TODO: 请在此处配置 API Key 或环境变量

输入：单个 C 源码文件

污点分析严格限制在当前文件内，不跨文件

文件访问限制为指定文件，不读取其他文件

安全权限、沙箱、资源限制不作考虑

6. 图编排要求
使用 LangGraph。

保留 A/B/C 的并行 fan-out 结构，但允许顺序调度。

图结构建议：

START -> A

START -> B

START -> C

A/B/C -> D 作为 join 节点

D 必须检查 A/B/C 三份报告是否齐全；只有三份都输入后才启动。

若未齐全，停止并报错，或等待补齐。

不考虑超时、重试、单 Agent 失败的复杂策略；但格式错误时需自动修复/重试。

7. D Agent 要求
D 必须具备以下能力：

等待 A/B/C 三份报告。

使用 LLM 语义相似度对 findings 去重。

调取对应原始报告中的判断内容和 confidence，进行冲突裁决，输出最终置信度与理由。

将原始报告和生成 Agent 写入 ledger。

将工具调用记录与 D 的假设验证推断写入 view。

调用工具验证污点假设。

写入记忆库后，再生成精简报告。

D 必须绑定工具调用能力，例如使用 llm.bind_tools([verify_taint]) 或 ToolNode 循环。

工具失败、超时、无结果时，停止并报错。

如果无法验证，标记为 uncertain 并说明原因。
