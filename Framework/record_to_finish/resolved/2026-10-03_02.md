# 测试记录 2026-10-03（第 2 次）

## 失败原因
- 现象：配置 API Key 后，程序调用线上 LLM 时**连接超时**，抛异常退出（`exit 1`）。
- 复现步骤：
  1. `config/.env` 已填入 `OPENAI_API_KEY`（`MODEL_NAME=gpt`）。
  2. 执行：`.venv/Scripts/python.exe main.py --file examples/input/sample.c`
- 期望结果：A/B/C 成功调用 LLM 完成扫描，输出含 `findings` 的 `output/final_report.json`。
- 实际结果：退出码 `1`。A/B/C 各耗时约 67s 后报错；异常链为
  `openai.APITimeoutError: Request timed out` ← `httpx2.ConnectTimeout: [WinError 10060] 连接尝试失败`；
  最终 `langchain_openai...OpenAITimeoutError` 未被捕获，经 `main.py:74 app.invoke` 冒出。
- 定位：网络层无法连通 LLM 服务主机（默认 `api.openai.com`）。
  关键栈：`agents/b.py:38 run` → `agents/__init__.py:218 run_scan_agent`
  → `agents/__init__.py:241 _scan_with_llm`（`llm.invoke(messages)`）。

## 改进建议
- **网络**：确认本机能访问目标 API 主机；如在受限网络，配置代理或改用可达的
  OpenAI 兼容服务地址（`OPENAI_BASE_URL`）。
- **模型名**：`MODEL_NAME=gpt` 非有效模型名，建议改为有效值（如 `gpt-4o-mini`）；
  本次因在连接阶段即超时，尚未走到模型校验。
- **代码健壮性**：`_scan_with_llm` 的 LLM 调用未捕获超时 / 网络异常，导致整个图崩溃。
  建议捕获后重试或降级并记录（参见 `QUESTION.md` 第 8 节错误处理策略）。

## 解决措施
- 将 `OPENAI_BASE_URL` 设为可达的中转站 `https://botcf.com/v1`，不再直连 `api.openai.com`，消除连接超时。
- 验证：后续测试不再出现 `ConnectTimeout`；2026-10-03 第 5 次测试成功跑通。
