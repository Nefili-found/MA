# 测试记录 2026-10-03（第 4 次）

## 失败原因
- 现象：把模型换成 `gpt-5.5` 后，A/B/C 扫描**成功**（各 `findings=1`），但在 D 的工具验证环节生成工具调用时报 400，程序退出（`exit 1`）。
- 复现步骤：
  1. `config/.env`：`MODEL_NAME=gpt-5.5`（base_url / key 不变）。
  2. 执行：`.venv/Scripts/python.exe main.py --file examples/input/sample.c`
- 期望结果：D 完成工具验证并写出 `output/final_report.json`。
- 实际结果：退出码 `1`。A/B/C 各约 64–69s 得到 `findings=1`；随后 dedupe≈25.6s、adjudicate≈14s、verify≈44s，最终报错：
  `openai.BadRequestError: Error code: 400 - 'A tool call is missing its matching output. Resend the complete tool-call and tool-output context.'`。
  关键栈：`verify_agent/d.py:105 run` → `:323 _verify_findings` → `:397 _invoke_verify` → `:423 _tool_loop`（`bound.invoke(messages)`）。
- 定位：`verify_agent/d.py::_tool_loop`（约 419–441 行）。循环先 `messages.append(resp)`（含 tool_calls 的 assistant 消息），
  但随后对 `tc.name != "verify_taint"` 的调用直接 `continue`，**未追加匹配的 `ToolMessage`**；
  下一次 `bound.invoke(messages)` 时该 tool_call 缺少匹配输出，违反 API 契约 → 400。
  （本中转站模型返回的工具调用 id / 名称与预期不完全一致时即触发。）

## 改进建议
- 保证「**每个 tool_call 必有匹配的 ToolMessage**」：对名称不符 / 无法执行的调用，也追加一条 `ToolMessage`（内容为错误说明），`tool_call_id` 取 `tc["id"]`。
- `_tool_loop` 失败时按 `QUESTION.md` 第 8 节**降级**（如回退为直接调用 `verify_taint`），避免整图崩溃。
- 可将工具循环次数 / 超时纳入配置。
